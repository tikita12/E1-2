# 대량 데이터 성능 측정

측정 시각: 2026-11-17T18:47:32+09:00

환경: Python 3.14.4, Linux-6.18.58.1-microsoft-standard-WSL2-x86_64-with-glibc2.43

실행 명령: `python3 tools/benchmark.py`

짧은 한글 문제와 선택지 4개를 생성하고, 임시 폴더에서 각 크기별 10회 측정한 중앙값이다. 저장에는 기존 JSON 읽기·검사 비용이 포함된다. 터미널 출력과 사용자의 답변 시간은 제외한다.

| 문제 수 | 파일 크기(bytes) | 저장(ms) | 불러오기(ms) | 마지막 문제 선형 탐색(ms) | 불러오기 Python 할당 최대(KiB) |
|---:|---:|---:|---:|---:|---:|
| 5 | 1177 | 0.214 | 0.074 | 0.003 | 134.3 |
| 1000 | 227937 | 17.921 | 4.229 | 0.076 | 1107.2 |
| 10000 | 2288937 | 206.208 | 53.075 | 0.694 | 10093.8 |

## 해석과 개선 방향

- 데이터 크기를 n으로 보면 전체 저장·불러오기·목록 순회는 O(n)이며, 메모리에 전체 목록을 보관한다. 질문 길이도 파일 크기와 메모리에 영향을 준다.
- 검색 메뉴는 아직 없다. 표의 탐색 값은 목록에서 마지막 문제를 찾는 순차 탐색 실험이다. 검색을 추가한다면 식별자와 딕셔너리 인덱스를 검토한다.
- tracemalloc 값은 불러오는 동안 새로 할당된 Python 메모리의 최대값이다. 프로세스 전체 RAM 사용량이나 이미 존재하는 퀴즈 목록의 메모리는 포함하지 않는다.
- OS 파일 캐시가 적용되는 반복 측정이며 다른 기기·긴 문제·느린 디스크에서는 결과가 달라진다. 1,000문제를 직접 출력하고 푸는 체감 시간과는 다르다.
- 대량 데이터에서는 목록 페이지 나누기, 문제 수 선택, SQLite 저장을 검토한다. 현재 과제에서는 요구된 JSON 형식을 유지한다.
